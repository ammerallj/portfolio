Giving Components an Identity

Duration
January 2021–2022
Role
UX Designer
Scope
Designed the early interaction model, component identity, and cross-app behavior that helped establish the foundation for Microsoft Loop.
Team
Design · Product Management · Research

Microsoft Loop (opens in new tab) introduced live, collaborative components that stayed up to date across Microsoft 365. The open question was how this new kind of object should behave and stay recognizable across products.

Approach

I defined the early interaction model for how Loop components should look, behave, and stay recognizable across Microsoft 365.

  • Keep the identity constant. Anchor name, sharing, and connection cues in one persistent control.
  • Separate what travels from what adapts. Keep core component structure and behavior consistent while letting each host app retain its own conventions.
  • Design portability as a behavior. Define how the component enters, loads, and responds across native and embedded contexts.

What changed

  • Give the component an identity of its own. I defined the core identity and interaction cues that kept a Loop component recognizable across Microsoft 365, later reflected in the patented model (opens in new tab).
  • Move collaborative components from concept into product. I helped shape the early interaction model and visual identity for the first components (opens in new tab), which shipped in Teams.
  • Create a structure others could build to. The component header and boundary established conventions that were later codified in Microsoft’s public developer guidance (opens in new tab).
